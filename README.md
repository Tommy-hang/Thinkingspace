# ThinkingSpace

> 把 AI 对话从一条时间线，变成一个可以探索的思维空间。

**在线体验**：https://tommy-hang.github.io/Thinkingspace/ · 当前版本 **V0.6.4**

支持桌面与手机浏览器。

<sub>
缘起：这个项目来自一次早八课前真实的思考火花——「为什么我明明想深入一个问题，最后却总是在翻聊天记录？」
原型由完全的 Vibecoding 在一天内搭出，之后持续迭代维护。故事不是重点，下面才是。
</sub>

## 写给谁用

**正在系统性地啃一大块新知识的人。**

一门全新的专业课、一篇读不懂的论文、一个从零开始的技术方向——
刚开始接触时，你会不断冒出疑问，而传统的 AI 聊天会让你越问越乱：

```text
读到一个新概念
      ↓ 冒出三个疑问
      ↓ 追着往下问
      ↓ 十分钟后
你已经想不起来，最开始到底在读什么
```

**你不缺 AI 的回答。你缺的是把这些回答组织成「自己的理解」的结构。**

ThinkingSpace 就是为这个场景做的：

| 你会遇到的处境 | 它怎么解决 |
| --- | --- |
| 一个小疑问打断了主线 | 选中回答里的任意一句话 → 开出**独立分支**，主线原封不动 |
| 问过的东西找不回来 | 每个主题在**地图**上有固定位置；最近 / 收藏 / 搜索随时跳回 |
| 越问越散，收不拢 | AI 把分支综合成**当前理解**，再生成整块知识的**知识点地图** |
| 总有几个问题没搞懂 | **待解决问题**全项目共享一份清单，解决后打勾 |

**不用注册就能完整使用**——内容只保存在你自己的浏览器里。
想换电脑、用手机继续，登录即可（支持 GitHub 一键登录）。

> 它不适合「今天天气怎么样」这类一次性提问——那些用普通聊天更快。

## 一、它要解决的问题

今天绝大多数 AI 产品，仍然沿用即时通讯软件的结构：一条不断向下滚动的消息流。

这种形式极其简单，也因此非常成功。但它与「复杂思考」之间有一个越来越明显的矛盾：

> **AI 的能力已经从「回答一个问题」进化为「辅助完成复杂研究」，而承载它的交互方式仍然是线性聊天记录。**

具体来说，有三个结构性缺陷：

### 缺陷 1：局部问题污染主线

```text
你正在读：Positional Encoding 的作用
        ↓ 突然对回答里的 QKV 产生疑问
        ↓ 追问 5 轮
        ↓
   原本的主线已经滚出屏幕，找不回来了
```

一个小的疑问，打断了你正在进行的理解。

### 缺陷 2：关系被压扁成顺序

```text
思考的真实结构              聊天记录里的样子

概念 A                      A
├─ 问题 A1                  A1
└─ 问题 A2                  A2
概念 B                      B
└─ 问题 B1                  B1
```

从属关系消失了，只剩时间顺序。

### 缺陷 3：上下文越滚越脏

传统做法把**全部历史**发给模型。轮次越多：

- Token 成本线性增长
- 无关内容稀释模型注意力
- 模型越来越难判断「你这句话在问什么」

## 二、我们的答案：改变最基本的单位

> **不再是「消息」，而是「主题」。**

```text
                    Transformer
                         │
        ┌────────────────┼────────────────┐
        │                │                │
   Attention      Positional Enc.       FFN
        │
   ┌────┴────┐
   │         │
  QKV    Multi-head
```

这张图不是事后自动生成的「漂亮思维导图」——**它就是你和 AI 进行思考的主要工作空间。**

### Topic · 主题卡片

一个认知主题 = **一张卡片**，而不是一条消息。

```text
┌────────────────────────────┐
│ Multi-head Attention       │
│ 为什么需要多个 Head？       │
│                            │
│ 6 轮 · 3 个分支 · 待解决 1  │
└────────────────────────────┘
```

卡片内部仍然可以有很多轮 Q&A，但它们**被关在这张卡片里**，不会污染别的主题。

> 200 条消息 ≠ 200 个节点。否则地图会迅速失去意义。

### Branch · 分支

在 AI 回答里**选中任意一句话**，就能从它生长出一个新的子主题。

而且分支会记住它**来自哪句话**：

```text
source node   →  Attention 机制
source message →  第 4 轮回答
anchor text    →  "The attention score is scaled by √dₖ"
```

所以模型知道你在问什么，而不需要猜「这里」指哪里。

### Map · 地图

所有主题构成一张**可以导航的地图**。

你不仅记得「我讨论过这个」，还记得**「它在思考空间的哪个位置」**——
这就是人类记忆里被无限滚动彻底放弃的**空间记忆**。

## 三、最核心的创新：结构本身成为 AI 的上下文

这是 ThinkingSpace 与所有「AI 聊天 + 可视化」产品的根本区别。

### 传统做法

```text
全部历史  →  全部发送给模型
```

### ThinkingSpace 的做法

```text
项目概述
   ↓  沿树向上，只取当前主题的祖先
上层主题摘要（每层截断）
   ↓
当前主题内部的对话
   ↓
分支锚点（你从哪句话分出来的）
   ↓
你现在的问题
```

**换句话说：用户看到的主题树，本身就是模型的上下文检索结构。**

```text
信息架构  =  用户的认知结构  =  模型的上下文结构
```

这三者第一次高度一致。带来的直接好处：

| | 效果 |
| --- | --- |
| Token 成本 | 只发相关内容，不随历史线性增长 |
| 回答质量 | 没有无关分支的噪声干扰 |
| 精确性 | 锚点让模型知道你具体在问哪一句 |

## 四、不只是发散，还能收敛

大多数 AI 工具只擅长「继续往下」。但真正的思考需要两步：

```text
发散  →  收敛
```

ThinkingSpace 两者都支持：

| 能力 | 说明 |
| --- | --- |
| **当前理解** | 每个主题由 AI 总结出的**结论性**概述（不是机械摘要） |
| **综合理解** | 把一个主题下的多个子分支，**收敛**成更高层的理解 |
| **知识地图** | 由全部卡片的「当前理解」生成整个项目的**知识点思维导图**，支持导出 PDF |
| **待解决问题** | 不只记录「我知道了什么」，也记录「我还不知道什么」——全项目共享一份清单 |

```text
回答 → AI 提议方向 → 你选择深入 → 形成理解 → 发现未解决问题
  ↑                                                    │
  └────────────── 综合理解（收敛）←────────────────────┘
```

---

## 五、AI 提议，用户决定

ThinkingSpace 不会变成「AI 自动创建几十个节点、自动连线、自动重构地图」的系统。

```
AI proposes  →  user decides
```

| AI 会做的 | AI 绝不会做的 |
| --- | --- |
| 提议 2–4 个值得继续探索的方向 | 自动创建节点 |
| 生成主题的「当前理解」 | 自动连接关系 |
| 综合子分支形成更高层理解 | 自动重构你的地图 |
| 建议一个知识点标题 | 覆盖你手动写下的标题 |

**地图始终属于用户。**

## 功能一览

### 空间化的思考

Conversation Map · Topic Card · Focus View（带空间过渡）· Branch（含锚点）·
Branch Intent（深入解释 / 为什么 / 举例 / **反例** / 建立联系 / 自定义）·
子树折叠 · 隐藏与恢复 · 思考路径高亮 · 悬停预览 · 自动布局

### 收敛与整理

当前理解（更新时给出 **+/− 版本差异**，确认后才生效）· 综合理解 ·
**综合节点**（多选主题 → 收敛成更高层认识，记录来源与未解决矛盾）·
待解决问题 · AI 探索方向建议 · 知识地图（+ PDF 导出）· 分支 Markdown 导出

### 回看与复盘

**思考回放**（拖动时间轴，看这棵树是怎么长出来的）· **当前理解的历史版本**

### 导航

最近浏览 · 收藏 · 全局搜索（`Ctrl+K`）· 主题直链 · 主题结构树

### AI 能力

**上下文透镜**（每条回答旁可展开，看见 AI 实际用了哪些内容——项目目标 / 上游主题 / 锚点 / 对话 / 引用）·
多模型切换（DeepSeek-V4.1-Flash / V4-Pro 等，支持自定义模型名）·
深度思考开关与强度 · 流式输出 · 联网搜索（Tavily / Exa / Serper）·
Markdown + KaTeX 渲染 · 多 Provider（DeepSeek / OpenAI / OpenRouter / 任意 OpenAI 兼容）·
离线演示模式（不配置任何 Key 也能体验）

### 日常使用

项目管理 · 节点状态与筛选 · 撤销重做 · 编辑提问并重新生成 ·
导入导出 · 使用说明面板 · 隐私说明 · 深浅色主题 · GitHub / 邮箱登录 ·
**跨项目拆分 / 复制分支**（把一张卡片连同它的全部子分支移动到或复制到另一个项目）

### 跨设备

- **手机浏览器可用**：左侧栏自动变成抽屉，顶部工具栏自动收纳，
  卡片上的操作按钮在触屏上常显（不依赖 hover）
- **云同步**：登录后项目自动同步，换设备能看到同一份内容
- **按需加载**：只拉取云端变过的项目，流量开销很小
- **同步冲突保底**：两台设备改了同一份内容时，会**自动保留两份**（把另一份另存为新项目），
  绝不静默覆盖；界面上会有醒目提示
- **自助删除账号**：账号面板里可一键注销，云端数据一并删除，无需联系维护者
- **用量提示**：账号面板显示已用项目数与内容体积，接近上限时提前预警

## 接入 AI

应用内提供了**分步图文教程**：设置 →「如何获取 API Key（详细教程）」，
或首次打开时的引导页最后一页。

简要步骤：

1. 到 [platform.deepseek.com](https://platform.deepseek.com) 注册并充值（10 元通常够问 1000 次以上）
2. 在 **API Keys** 页面创建一个 Key（以 `sk-` 开头，**只显示一次**，记得先存好）
3. 回到本站 → 设置 → **AI Providers** → DeepSeek → 粘贴 Key → 点「设为当前」
4. 回到主题中提问

**联网搜索**（可选）：到 [tavily.com](https://tavily.com) 注册（有免费额度）拿 Key，
填进 设置 →「联网搜索」，再打开输入框上方的 🌐 开关。

> 未配置 Key 时默认使用「离线演示」模式，界面流程完全可用，只是回答是预设文本。
> **API Key 只保存在你自己的浏览器里，不会上传，也不参与导出。**

## 数据与隐私

- 不登录时，内容只保存在**你自己浏览器的 localStorage**
- 登录后，项目同步到云端（Supabase），**数据库层强制隔离，只有你能读到自己的数据**
- **API Key 只保存在本机浏览器**，不参与导出，也不进入代码仓库
- 导出的 `.thinkingspace.json` 只包含项目内容
- ⚠️ 清理浏览器数据会导致本机内容不可见，**请定期导出备份**

详见应用内 **设置 → 隐私与数据**。

## 设计原则

1. **AI 提议，用户决定。** 不自动创建节点、不自动连线、不自动重构地图。
2. **内容优先，低视觉噪声。** 地图是为思考服务的，不是为炫技服务的。
3. **上下文要精准，而不是越多越好。** 只发送与当前主题真正相关的内容。
4. **数据属于你。** 本地优先、密钥不上传、随时可完整导出。

## 自建部署（可选）

想用自己的 Supabase 项目跑一份：

1. 在 [supabase.com](https://supabase.com) 建一个项目
2. 把 `supabase/schema.sql` 的内容粘到 **SQL Editor** 执行
   （可重复运行；包含建表、表级授权、RLS 策略、容量保护）
3. `Authentication → Providers` 启用 **GitHub**
   （需要自建 GitHub OAuth App，回调地址填 `https://<项目>.supabase.co/auth/v1/callback`）
4. `Authentication → URL Configuration` 把站点地址加进 **Redirect URLs**
5. 本地：复制 `.env.example` 为 `.env.local`，填入 `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`
6. 线上：仓库 `Settings → Secrets and variables → Actions → Variables` 配同名两个值

### 可选：每日自动备份

Supabase 免费版**没有自动备份**。仓库里的 `.github/workflows/backup.yml`
每天导出一次数据库并保存为 artifact（保留 90 天）：

1. Supabase → `Project Settings → Database → Connection string` 复制 **URI**
2. 仓库 `Settings → Secrets and variables → Actions → Secrets` 新建
   `SUPABASE_DB_URL`，值为那个 URI
3. 到 Actions 页面手动运行一次 `Daily database backup` 验证

> 备份失败时 GitHub 会自动发邮件通知。

### 容量保护

`supabase/schema.sql` 里的触发器限制：

| 限制 | 默认值 |
| --- | --- |
| 每个账号项目数 | 20 |
| 每个账号内容总量 | 20 MB |
| 单个项目内容 | 4 MB |

数字可直接在 SQL 里改，改完重新运行即可。

### 保持项目活跃

Supabase 免费项目 **7 天无访问会被暂停**。`.github/workflows/keep-alive.yml`
每天访问一次数据库来避免。

> 注意：GitHub 的定时工作流在仓库 **60 天无活动**后会被自动禁用。
